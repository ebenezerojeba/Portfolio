GetConfident

An AI impromptu speaking coach that gives instant feedback on clarity, structure, confidence, pace and filler words.

View live site (opens in a new tab) Source on GitHub (opens in a new tab)

Overview

GetConfident helps people practise impromptu speaking out loud for interviews, presentations and everyday conversations. The user chooses a practice mode, gets a random topic, records an answer against a timer, and receives specific AI coaching on clarity, structure, confidence, pace and filler words.

The core loop is: choose a mode, get a topic, count down, record, transcribe, analyse, review, practise again and track progress over time.

The problem it solves

Most people only practise speaking when it already matters: in the interview or the meeting. GetConfident gives them a low-stakes place to practise under a little time pressure and get specific, actionable feedback straight away, instead of generic advice.

My contribution

Product design and full-stack development: the practice flow, recording and transcription pipeline, AI coaching integration, authentication, progress tracking, achievements and the automated test suite.

Key features

  • Practice modes with a library of seeded speaking topics and a 3-2-1 countdown.
  • In-browser recording with camera or voice only.
  • Speech transcription followed by structured AI coaching on clarity, structure, confidence, pace and filler words.
  • Filler-word detection and pace measured in code, not left to the model.
  • Progress tracking with charts, practice history, streaks and achievements.
  • Follow-up questions, notifications and an hourly notification job.
  • Accounts with onboarding, settings and session management.

Architecture overview

  • Next.js App Router with route groups for marketing, auth, the app and the API. Business logic lives in feature modules rather than page components.
  • PostgreSQL with Prisma. Authentication is built in-house with Argon2id password hashing and database-backed sessions. Every request resolves the user server-side, and another user's resource returns 404.
  • AI output is never trusted raw. The model is called through the OpenAI REST API with a strict JSON schema; the response is parsed, normalised and validated with Zod. Pace, pause and filler scores are overridden by deterministic measurements, and metrics the app can't measure are shown as unavailable rather than invented.
  • A clearly labelled mock AI provider lets the whole flow run offline in development and refuses to run in production.
  • Tested with Vitest unit and integration tests against a real database, and Playwright end-to-end tests including accessibility (axe), security header and Core Web Vitals checks.
